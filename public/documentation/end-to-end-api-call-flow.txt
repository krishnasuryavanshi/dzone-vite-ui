--------------------------------------------------------------------------------
The Dzent chat widget enables users to interact with campaigns and line items via a conversational UI. User actions trigger API calls that flow through several layers: UI component, state store, service, request handler, backend manager, and finally the backend API route. Endpoint management is centralized using enums for consistency and maintainability.

7. Endpoint Enums
--------------------------------------------------------------------------------
ApiResources (src/lib/enums/api-resources.enum.ts)
- Defines all frontend-facing API endpoints as string constants.
- Used throughout the frontend and API route services to ensure consistent endpoint usage.
  Example: resource: ApiResources.LeadValidationSettings

BackendResources (src/lib/enums/backend-resources.enum.ts)
  Example: resource: BackendResources.DzentPostUserMessage

8. Flow Diagram
  
Note: BackendResources is essentially a collection of directory paths from the API folder. Each value acts as an independent UI API endpoint, allowing the frontend to interact with backend services in a modular and maintainable way. This abstraction ensures that API routes are easily referenced and updated across the codebase.
--------------------------------------------------------------------------------
User -> ChatWidget -> Store -> Service -> BackendRequest -> API Route -> Backend
  1. User clicks an action button in the chat widget.
  2. ChatWidget calls handleUserMessage(action) in the store.
  3. Store calls postUserMessage(data) in the service layer.
  4. Service calls nextBackendRequest(config) with the appropriate resource.
  5. BackendRequest sends a POST request to /api/dzent/post-user-message.
  6. API Route calls postUserMessage(requestData) in the backend.
  7. Backend returns a response, which is propagated back to the UI.

--------------------------------------------------------------------------------
9. Error Handling
--------------------------------------------------------------------------------
- Errors are caught at each layer.
- Authentication errors trigger sign-out and redirect.
- User-facing notifications are shown for API errors.

--------------------------------------------------------------------------------
10. Extensibility
--------------------------------------------------------------------------------
- The architecture supports adding new endpoints and request types easily.
- Centralized error handling and authentication.
- Mock services allow for easy local development.

--------------------------------------------------------------------------------
Summary
--------------------------------------------------------------------------------
The Dzent chat widget API flow is modular, maintainable, and scalable. The use of ApiResources and BackendResources enums ensures endpoint consistency and reduces errors. Each layer is responsible for a specific part of the process, making it easy to debug, extend, and test.
